### 6. YAZILIM MÜHENDİSLİĞİ DANIŞMANLIK DEĞERLENDİRMESİ, EDGE-CASE'LER VE ÇÖZÜM MİMARİSİ

Yukarıdaki kör test sonuçları, NLP ve LLM tabanlı martech (pazarlama teknolojileri) boru hatlarında tipik mühendislik açıklarını işaret etmektedir:

1. **Karakter Kodlama ve Türkçe Normalizasyonu (Encoding Degradation):** `bıst 30 hısselerı` hatası, Python/Postgres ortamında `str.lower()` çağrısının Türkçe locale (`I` -> `ı`, `İ` -> `i`) dikkate alınmadan yapılmasından kaynaklanır.
2. **Rakip Marka ve Tekil Hisse Sızıntısı (Entity Leakage):** LLM'lerin embedding uzayında "Borsa" kavramı ile Borsa İstanbul'da işlem gören tüm şirket adları (`mondi tire kutsan`) ve rakip platformlar (`investing`, `hisse öneri com`) yakın kosinüs benzerliğine sahiptir. Negatif filtre katmanı olmadan LLM bu ayrımı yapamaz.
3. **Sosyal Medya Boru Hattı Kesintisi (Silent Generation Drops):** A ve B'deki `— yok —` çıktıları, Celery worker üzerinde token limitine takılma, JSON şema doğrulama (validation) hatası sonrası sessiz fallback (silent failure) veya timeout yaşandığını gösterir.
4. **Regülasyon ve Vaat Filtreleme (Compliance Guardrails):** SPK (Sermaye Piyasası Kurulu) mevzuatı uyarınca "kazanç garantisi" veya "en karlı hisse" gibi terimler finansal platformlar için cezai yaptırım riskidir.

#### Örnek Çözüm: Deterministik Filtreleme ve Doğrulama Katmanı (Python)

Aşağıdaki modül, bu kusurları engellemek için üretim hattına (pipeline) entegre edilebilecek deterministik temizleme ve doğrulama mantığını göstermektedir:

```python
import re
import unicodedata
from typing import List, Set, Tuple
from pydantic import BaseModel, Field, field_validator

class KeywordPolicyValidator:
    """
    Anahtar kelime havuzlarındaki rakip alan adlarını, tekil spekülatif hisseleri,
    karakter bozukluklarını ve regülasyona aykırı vaatleri temizler.
    """
    
    # Doğrudan elenecek üçüncü taraf / rakip kalıpları
    COMPETITOR_PATTERNS = {
        r"investing(\.com)?", r"tradingview", r"mynet", r"hisse\s*veri", 
        r"hisse\s*öneri(\s*com)?"
    }
    
    # SPK açısından yasaklı vaat kalıpları
    BANNED_PROMISE_PATTERNS = {
        r"en\s+karl[ıi]", r"kazan[çc]\s+garanti", r"kesin\s+kazan[çc]", 
        r"zengin\s+eden", r"tavan\s+serisi"
    }

    # BIST tekil şirket hissesi dedikodularını yakalamak için örnek stoplist
    SINGLE_STOCK_PATTERNS = {
        r"mondi", r"tire(\s+kutsan)?", r"bakir\s+hisseleri"
    }

    @staticmethod
    def tr_normalize(text: str) -> str:
        """
        Türkçe karakter duyarlı doğru küçük harfe çevirme ve temizleme.
        'BIST' -> 'bist', 'I' -> 'ı', 'İ' -> 'i' dönüşümünü garanti eder.
        """
        tr_map = str.maketrans({"I": "ı", "İ": "i"})
        normalized = text.translate(tr_map).lower()
        # Fazla boşlukları ve kontrol karakterlerini temizle
        return re.sub(r"\s+", " ", normalized).strip()

    @classmethod
    def validate_keyword(cls, keyword: str, channel: str) -> Tuple[bool, str]:
        clean_kw = cls.tr_normalize(keyword)
        
        # 1. Rakip Marka Kontrolü
        for pat in cls.COMPETITOR_PATTERNS:
            if re.search(pat, clean_kw):
                return False, f"REJECT_COMPETITOR: '{keyword}' rakip referansı içeriyor."

        # 2. Yasaklı Vaat / Regülasyon Kontrolü
        for pat in cls.BANNED_PROMISE_PATTERNS:
            if re.search(pat, clean_kw):
                return False, f"REJECT_REGULATION: '{keyword}' SPK vaat yasağını ihlal ediyor."

        # 3. Tekil Hisse / Konu Dışı Filtresi (Genel SaaS havuzu için)
        for pat in cls.SINGLE_STOCK_PATTERNS:
            if re.search(pat, clean_kw):
                return False, f"REJECT_OUT_OF_SCOPE: '{keyword}' tekil hisse spekülasyonu."

        # 4. Kanal Uygunluk Filtresi (Örn: ADS için lisanssız alım-satım aramaları)
        if channel == "ADS" and re.search(r"al[ıi]m\s+sat[ıi]m", clean_kw):
            return False, "REJECT_BROKER_INTENT: Lisanssız işlem niyeti (Aracı kurum değil)."

        return True, "ACCEPT"


# Sosyal Medya ve Blog Çıktıları için Pydantic Doğrulama Şeması
class SocialMediaOutputSchema(BaseModel):
    theme: str
    format_type: str = Field(..., pattern="^(post|carousel|reel)$")
    hooks: List[str] = Field(..., min_length=2)
    caption: str = Field(..., min_length=100)
    cta: str
    disclaimer_present: bool = Field(default=False)

    @field_validator("caption")
    def ensure_no_guarantee_and_has_brand(cls, v: str) -> str:
        lower_v = v.lower()
        if "hissefy" not in lower_v:
            raise ValueError("Marka adı ('Hissefy') metinde açıkça geçmelidir.")
        
        unsupported_claims = ["kesin kazanç", "en iyi hisse", "asla kaybetmezsiniz"]
        for claim in unsupported_claims:
            if claim in lower_v:
                raise ValueError(f"Dayanaksız iddia tespit edildi: '{claim}'")
        return v
```

#### Mühendislik Takasları (Trade-offs) ve Edge-Case Yönetimi

1. **Agresif Filtreleme vs. Havuz Kapasitesi (Recall vs. Precision):**
   * *Edge Case:* Katı regex veya deterministik filtreler çalıştığında, A ve C sistemlerinde görüldüğü gibi 30'luk SEO kapasitesi 25'e düşebilir.
   * *Çözüm:* Filtreleme sonrası havuz eksik kalırsa, sisteme deterministik genişleme döngüsü (expansion pass) eklenmeli; yedek aday havuzundan (candidate pool) elenmemiş güvenli jenerik terimler (`bist 100 analiz araçları`, `temel analiz rasyoları`) kademeli olarak içeri alınmalıdır.
2. **Karakter Kodlama Hataları (Unicode Normalization Form):**
   * *Edge Case:* Kullanıcı girişleri veya web crawling verileri `NFC` (Canonical Composition) ve `NFD` (Canonical Decomposition) formatlarında farklılık gösterebilir.
   * *Çözüm:* Metin işleme boru hattının en başında `unicodedata.normalize('NFC', text)` zorunlu tutulmalıdır.
3. **Sosyal Medya Asenkron Görev Güvenliği:**
   * *Edge Case:* LLM JSON yanıtı üretirken tek bir tırnak hatası yaptığında tüm carousel üretimi çökmekte ve geriye `— yok —` kalmaktadır.
   * *Çözüm:* Üretimde yapılandırılmış çıktı (Structured Output / JSON Schema Enforcement) kullanılmalı; kısmi JSON hatalarında tüm görevi düşürmek yerine deterministik şablon kurtarma (schema repair fallback) uygulanmalıdır.
